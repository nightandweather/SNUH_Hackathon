# ICU 가상병동 작업물 사용방법

최신 전체 상황판부터 보려면 **icu-board-demo.zip**을 내려받는다. Google Drive의 HTML 미리보기를 여는 방식이 아니라, 압축을 풀고 Python 서버를 실행해 브라우저로 접속하는 방식이다.

## 1. 어떤 파일을 쓰면 되는가

| 작업물 | 용도 | 접속 주소 |
| --- | --- | --- |
| icu-board-demo.zip | 4층·8개 ICU·64병상 전체 상황판, 3교대, 인계, 응급상황, 시연용 MD | http://127.0.0.1:8000/ |
| 같은 전체 상황판의 간호사 로그인 | 같은 환자·교대 경과에서 각 직원의 담당 화면 보기 | http://127.0.0.1:8000/nurse |
| ward-pod-demo.zip | 간호사·수간호사 로그인과 담당 환자 접근 범위를 확인하는 별도 6환자 데모 | http://127.0.0.1:8001/ |
| README.md | 전체 상황판의 상세 설명과 Pod 모델·데이터 연결 설정 | 문서 |

전체 상황판과 `/nurse` 로그인 화면은 같은 서버의 64병상·3교대 경과를 공유한다. 상황판 상단의 간호사 선택은 전체 지도에서 시점을 바꾸는 시연 기능이며, 개인 계정 로그인은 `간호사 로그인`에서 한다. 별도 `ward-pod-demo.zip`은 기존 6환자 실험용 프로그램으로 현재 상황판과 데이터를 공유하지 않는다.

## 2. 전체 상황판 실행

1. `icu-board-demo.zip`을 내려받아 압축을 푼다. `start-original-icu.command`와 `icu-board` 폴더를 함께 둔다.
2. Python 3.10 이상이 필요하다. 터미널에서 `python3 --version`으로 확인한다. Python 패키지를 별도로 설치할 필요는 없다.
3. macOS에서는 `start-original-icu.command`를 실행한다. 터미널로 실행하려면 압축을 푼 폴더에서 다음 명령을 사용한다.

   ```sh
   /bin/zsh ./start-original-icu.command
   ```

4. 브라우저 자동 열기가 되지 않으면 `http://127.0.0.1:8000/`으로 접속한다. 실행한 터미널을 계속 열어 둔다.
5. 종료하려면 터미널에서 `Ctrl+C`를 누른다.

Windows·Linux 또는 Pod에서는 다음처럼 실행한다. Windows에서 명령 이름이 `python`이면 `python3` 대신 사용한다.

```sh
cd icu-board
python3 server.py
```

Google Drive 폴더 전체를 다운로드했다면 `server.py`가 있는 폴더에서 바로 `python3 server.py`를 실행해도 된다. 실행 파일도 같은 폴더에 둘 수 있다. 전체 상황판 ZIP에는 공개 데모의 환자 재생 자료와 공개 예시 흉부 영상이 포함되어 있어 모델 연결 없이 화면과 기록 기반 인계를 시연할 수 있다.

## 3. 화면을 보는 방법

- 네모는 병상이다. 환자가 있는 병상을 누르면 현재 상태, 담당 간호사, 진행 중인 사건을 본다.
- 간호사 표식을 누르면 소속 ICU, 담당 환자, 활동과 피로도를 본다. `MD` 표식은 별도 시연용 의사이다.
- 상단의 `병동 전체 화면`은 전체 배치를 보여준다. 간호사를 선택하면 해당 간호사의 담당 화면으로 바뀐다.
- 환자 배정·동료 대신 보기·응급 출동은 같은 ICU 안에서만 한다. 병동 내 가용 간호사가 부족하거나 MD가 다른 사건에 대응 중이면 부족·대기로 표시한다.
- 간호사·MD의 위치, 인원과 피로도는 시뮬레이션이다. 실제 병원 위치나 근무 기록을 측정한 값이 아니다.
- 직원이 모이면 표식을 조금 벌려 표시한다. 가는 선과 작은 점이 원래 위치이며, 전체 직원 ID는 마우스를 올리거나 키보드로 포커스하거나 표식을 선택하면 ICU 위쪽에 표시된다.

## 3-1. 간호사 로그인 후 보이는 화면

상황판 상단의 `간호사 로그인`을 누르면 별도 탭에서 `/nurse`가 열린다. 현재 실행이 8001번 포트라면 `http://127.0.0.1:8001/nurse`를 사용한다. 계정 목록에서 직원을 고르고 공통 **시연 PIN `2026`**으로 로그인한다. D는 데이, E는 이브닝, N은 나이트이다.

| 시연 계정 예시 | 로그인 후 보이는 범위 |
| --- | --- |
| `D-MICU-1` | 데이 근무 중인 내과 ICU 담당 간호사: 담당 환자, 대신 보는 환자와 현재 응급 출동 환자 |
| `D-MICU-C` | 데이 근무 중인 내과 ICU 책임 간호사: 내과 ICU 전체 |
| `HN01` | 전체 수간호사: 8개 ICU 전체 환자·알림·인계 조회 |
| `E-MICU-1`, `N-MICU-1` | 해당 조가 근무 중일 때 담당 화면, 비근무 시간에는 다음 근무 안내 |

개인 화면에는 현재 근무·소속 ICU, 담당 환자의 HR·MAP·SpO₂·RR와 위험지표, 관련 알림·MD 대응, 검사 진행, 내가 저장한 수행 기록, 인계 자료가 보인다. 환자를 선택해 수행 보고를 저장하거나 검사 업무를 시연하고, 실제 인계 수신자 계정으로 확인·질문을 남긴다. 사용자 입력 수행 보고와 시뮬레이션 활동은 구분한다. `HN01`은 조회용이며 일반 간호사 대신 기록을 작성하지 않는다.

포털의 환자 범위와 수행자는 서버가 로그인 계정과 현재 배치에서 정한다. 다른 직원·역할 ID를 요청에 넣어도 해당 포털 권한이 늘어나지 않는다. 로그인은 시연용 메모리 세션이고 서버 재시작 시 풀린다. 전체 상황판은 공개 데이터의 운영 시연 화면으로 계속 제공되므로 실제 병원 개인정보 접근 통제를 대체하지 않는다.

## 4. 수행 기록과 인계

1. 상단에서 간호사를 고르고 그 간호사의 환자가 있는 병상을 선택한다.
2. 환자 상세의 `AI 상담`을 연다.
3. `내가 수행한 내용 · 사용자 입력`에 시연 기록을 입력한다. 예: `시연 입력: 상태 확인 후 담당 MD에게 보고함.`
4. `기록 저장`을 누른다. 일반 대화와 AI 권고는 수행 이력으로 자동 저장되지 않는다.
5. `근무 인계`를 누르거나 채팅에 `내가 여태 뭘 했는지 환자 상태와 같이 인계해줘`라고 입력한다.
6. 내 이번 근무 수행 기록, 이전 조·동료의 기록, 현재 환자 상태, 미해결 사건과 MD 상태를 확인한다.

출동·도착·대응 종료·동료 대신 보기는 별도의 **시뮬레이션 활동 기록**이다. 실제 처치 수행 보고와 구분된다. 모델 연결이 없으면 `규칙 기반 출력`으로 표시되며 저장 기록과 현재 상태를 바탕으로 인계를 만든다. 모델이 작성한 검토 항목은 별도 초안으로 표시된다.

교대 시각에는 이전 담당자와 다음 담당자, 그 순간의 환자 상태와 미완료 검사·응급 대응을 묶어 인계 자료를 만든다. 자료 생성과 받는 사람의 확인은 별도 단계다. `최근 교대 인계 자료`에서 받는 담당자 역할로 `인계 확인`을 누르면 수신 시각·직원 ID가 기록된다. 질문을 저장하면 `질문 접수·답변 대기` 상태가 남으며, 확인 버튼을 다시 눌러도 미답변 질문이 사라지지 않는다. 질문은 시연 자료에 저장되며 이전 간호사에게 실제로 전송되지 않는다. AI 상담은 저장된 내용을 설명하는 별도 초안이다.

환자 또는 근무자가 바뀌면 상담창을 다시 열어 현재 환자·직원을 확인한다. 수행 기록과 인계는 현재 실행의 메모리에 저장되므로 새 시나리오나 서버 재시작 시 초기화된다.

## 5. 3교대 보기

- 데이: 07:00–15:00, 이브닝: 15:00–23:00, 나이트: 23:00–07:00.
- 각 조 40명, 총 120명의 직원 ID를 구분한다. 화면에는 현재 조 40명이 표시된다.
- `다음 교대까지`를 누르면 환자 경과와 사건을 다음 교대 시각까지 진행한 후 일시정지한다.
- 오른쪽 ICU 선택과 `최근 교대 인계 자료`에서 이전 담당자→새 담당자, 환자 상태, 저장 기록과 미해결 사건을 확인한다.
- 교대 15분 전에는 인계 준비 표시가 나온다. 최대 24시간의 3교대 경과를 본 뒤에는 새 시나리오로 다시 시작한다.

교대 시간을 바꾸려면 `units.json`의 근무표를 수정한다. 새 시나리오를 시작하기 전에 필요한 기록을 확인한다.

간호사 일상 순회는 개인마다 첫 1–15분, 이후 10–20분 간격으로 진행해 동시에 출발하지 않는다. 고정 휴식에도 ±10분 차이를 두고 교대마다 새 일정을 만든다. 응급 출동·MD 호출은 그대로 즉시 배치한다.

## 5-1. 환자 바이탈과 검사 업무

1. 환자가 있는 병상을 누르면 현재 HR·MAP·SpO₂·RR와 최근 2시간 추세가 보인다. 현재 입원 이후 실제로 재생한 시점만 표시한다. 결측은 기록 없음이며, 이전 기록값 유지가 새 측정을 의미하지 않는다.
2. `채혈 시연`을 누르고 재생하면 담당 간호사의 이동 → 채혈 단계 → 검체 이송을 본다. 실제 검사 결과 수치는 연결되어 있지 않다.
3. `포터블 X-ray 시연`은 간호사 준비 → 촬영 호출 → 기사 대기·촬영 → 예시 영상 표시로 진행한다. 응급 대응 중이면 검사 업무가 대기하고, 교대 때 미완료 상태가 인계에 포함된다.
4. 영상 표시 단계에서 `VL 영상 검토`를 누른다. 화면의 영상은 공개 NIH ChestX-ray14 예시이며 이 환자의 실제 검사 영상이 아니다.
5. 이미지 입력이 가능한 모델이 연결되면 검토 초안과 실제 모델 이름을 표시한다. 연결이 없거나 응답에 실패하면 `영상 검토 미실행`으로 표시한다. 공개 예시의 라벨을 새 판독 결과로 보여주지 않는다.

실제 MIMIC 검사·영상 연결은 별도 구현이다. [검사 기록](https://mimic.mit.edu/docs/iv/modules/hosp/labevents.html)의 채취·결과 공개 시점과 [MIMIC-CXR](https://physionet.org/content/mimic-cxr-jpg/2.1.0/)의 환자 ID·촬영 시각·입원 시간창을 함께 맞춰야 한다.

## 6. 코드블루·저산소증·저혈압 시연

1. 환자가 있는 병상을 선택한다.
2. 상세의 `응급상황 시연`에서 `코드블루 시연`, `저산소증 시연`, `저혈압 시연` 중 하나를 누른다.
3. 재생 중이면 같은 ICU 간호사의 출동·도착과 MD 호출·이동·도착을 확인한다. 일시정지 중이면 재생을 눌러 진행한다.
4. 인력 부족이나 MD 대기가 있으면 진행 중 사건에 표시된다. 다른 ICU의 일반 간호사를 자동으로 데려오지 않는다.
5. 인계에서 해당 사건과 MD 대응 상태가 미해결 사항으로 표시되는지 확인한다.

같은 병상에 진행 중 사건이 있으면 새 응급 시연을 중복 시작할 수 없다. 시연 활력은 원자료와 분리해 표시하고, 종료 후에는 현재 시각의 원자료 재생값으로 돌아간다. 사건 해소 시간과 인원은 운영 시연을 위한 가정이며 검증된 치료 반응이나 실제 치료 성공률이 아니다. 공개 예시 X-ray도 해당 환자의 실제 검사 영상이 아니다.

EICU는 응급 ICU 병동 설정이며 별도의 응급실 접수·분류·ICU 전입 경과는 없다. 심정지 대응 타이머 종료를 소생 또는 사망 확인으로 해석하면 안 된다. 테이블 데스 등 시술 중 사망과 사후 업무도 현재 시연에는 포함되어 있지 않다.

## 7. 별도 로그인 데모

`ward-pod-demo.zip`은 별도 폴더에 푼다. 원본 환자 CSV와 API 키는 들어 있지 않으므로 승인된 데이터 경로를 지정해야 한다. 공개 MIMIC 데모의 경우:

```sh
WARD_SOURCE=mimic WARD_DATA_DIR=/path/to/mimic-iv-demo python3 ward_server.py
```

`/path/to/mimic-iv-demo`는 실제 폴더로 바꾼다. `icustays`, `d_items`, `chartevents`, `inputevents` CSV 또는 CSV.gz가 필요하며 `procedureevents`는 선택 항목이다. 전체 상황판의 `pool_mimic.json`은 이 CSV 대신 사용할 수 없다.

접속 주소는 `http://127.0.0.1:8001/`이다. 시연 계정 RN01·RN02·RN03은 각 담당 환자 2명을, HN01은 6명 전체를 본다. 공통 시연 PIN은 `2026`이다. 실제 병원 계정과 연결된 인증이 아니다. 상세 설정은 ZIP 안의 `WARD_WORKFLOW.md`를 참고한다.

## 8. KHDP Pod 모델 연결

전체 상황판은 `LLM_BASE_URL`, `LLM_MODEL`, `LLM_API_KEY`를 사용한다. 별도 로그인 데모는 Qwen용 `WARD_QWEN_*`와 GLM용 `WARD_GLM_*` 설정을 따로 사용한다. 주소와 모델 ID는 Pod에 실제로 배포된 값으로 설정하고 API 키는 환경변수로 넣는다.

K-MIMIC 데이터는 승인된 Pod 경로를 사용한다. 전체 상황판은 `kmimic.py`로 변환한 뒤 `POOL=kmimic`으로 실행하며 병원별 항목 매핑을 확인해야 한다. 실제 K-MIMIC·GLM 연결은 아직 검증하지 않았다. 현재 기능은 기록 재생과 운영 시뮬레이션이며 치료 결과 예측이나 강화학습 검증을 완료한 디지털 트윈은 아니다.

## 9. 안 열리거나 예전 화면이 보일 때

- `Address already in use`가 나오면 기존 서버 터미널에서 `Ctrl+C`로 종료한 뒤 다시 실행한다. 기존 프로세스가 실행 중이면 새 코드를 저장해도 화면이 자동으로 바뀌지 않는다.
- 최신 ZIP을 풀었는지, 그 폴더에서 실행했는지 확인하고 브라우저를 새로고침한다.
- 전체 상황판은 8000번, 로그인 데모는 8001번이다. 주소를 확인한다.
- 모델이 연결되지 않아도 전체 지도와 기록 기반 인계는 사용할 수 있다. GLM 응답 확인은 Pod의 실제 모델 연결 후 진행한다.
- HTML 파일만 직접 열면 서버 API가 없어 작동하지 않는다. Python 서버의 주소로 접속한다.

## 10. 확인한 범위

전체 테스트 111개, 공개 MIMIC 재생의 고정·자동 배치 8시간·24시간 검사, JavaScript VM·간이 DOM 검사가 통과했다. 같은 서버의 `/nurse`에서 HTTP 인증·환자 범위 검사 10개와 실제 브라우저의 일반 간호사·책임간호사·수간호사·비근무 계정 화면도 확인했다. 시연 계정은 121개이며 점검 시각에는 일반 간호사 담당 환자 2명, 책임간호사 소속 ICU 환자 5명, 수간호사 전체 환자 44명이 표시됐다. 이 수는 당시 입원·배치 상태이며 고정 환자 수가 아니다. 전체 상황판의 직원 표식 48개는 몸체 겹침 0건이었다.

결과는 `verification/checks.json`, `verification/handover-offline.json`, `verification/nurse-http-check.json`, `verification/nurse-browser-check.json`에 있다. 브라우저 점검에서 인계 수신 확인을 직접 생성하지는 않았으며 해당 권한과 교대 변경은 API 테스트로 검증했다. 실제 GLM/Qwen 추론과 K-MIMIC 연결은 확인하지 못했다. 영상 모델 성공 경로는 모의 응답으로 검증하며 실제 모델 호출 성공을 뜻하지 않는다.
