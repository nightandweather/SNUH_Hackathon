이 안내는 합성 환자를 사용하는 ICU 예약·업무 시연의 현장 실행용입니다. ChatGPT/Codex는 앱 실행 의존성이 아닙니다. 모델이 없어도 규칙 기반 합성 모드를 사용할 수 있습니다.

1. **반입·환경 확인**

   코드·패키지·예시 자료 반입 허용 여부는 아직 확인하지 않았습니다. ZIP이나 환경 예시를 만들었다는 사실이 반입 승인은 아닙니다. 행사 담당자에게 허용된 반입 방법, 실행 환경, 포트 접근, 데이터 이용·반출 범위를 확인하세요. 학습·모델 API 지원·마감 규정은 이 안내에서 추측해 확정하지 않습니다.

   Python 3.10 이상이 필요합니다. 앱과 `pod_check.py`는 표준 라이브러리를 사용합니다. 별도 `kcd-2026/probe/probe_api.py`와 gateway는 선택 사항이며 `openai` SDK가 필요합니다. Docker를 선택하면 기반 이미지 준비도 필요하고, 실제 Pod Docker 실행은 검증하지 않았습니다.

   전달 패키지 이름은 `icu-pod-ready.zip`이며 별도 실행 안내용 `start-pod-demo.command`가 있습니다. 반입이 허용된 환경에서 압축을 풀어 사용하세요. 아래 Python 명령으로도 실행할 수 있습니다.

2. **완전 오프라인 합성 실행**

   터미널에서 압축을 푼 `icu-board` 폴더로 이동합니다. HTML 파일을 직접 열면 API가 연결되지 않습니다.

   ```sh
   python3 pod_check.py --offline
   OFFLINE_DEMO=1 PORT=8002 python3 server.py
   ```

   브라우저 주소는 `http://127.0.0.1:8002/planning`입니다. 환경의 포트 전달 방식이 다르면 승인된 Pod 접근 주소를 사용합니다. 실제 포트 접속은 이 검사기의 확인 범위 밖입니다.

   `--offline`은 기본값이며 실제 모델을 호출하지 않습니다. 파일이 생성 중이면 `pending`, 오류가 있으면 `fail`로 표시하고 종료 코드는 1입니다. 모든 필수 검사가 통과해야 `offline_ready=true`와 종료 코드 0이 됩니다. `pass`도 반입 승인·실제 환자 연결·임상 효과를 뜻하지 않습니다.

   `OFFLINE_DEMO=1`은 외부 자료 다운로드를 차단하는 설정입니다. 명시적으로 선택한 승인된 내부 모델 API 요청까지 차단하는 설정은 아닙니다. 모델 호출도 하지 않으려면 `PLANNER_MODE=offline`을 유지하고 `pod_check.py --model`을 실행하지 마세요. 서버 종료는 실행한 터미널의 Ctrl+C입니다.

   기존 터미널에 `POOL`을 설정해 두었다면 합성 실행에서는 `POOL=synth`로 지정하세요. 서버는 폴더의 `.env.pod` 또는 명시한 `POD_ENV_FILE`을 읽으며, 이미 내보낸 환경변수를 우선합니다. 일반 `.env` 파일은 자동으로 읽지 않습니다. 검사기에는 4번처럼 환경변수를 명시적으로 적용합니다.

3. **환자 경과와 실자료 적용 범위**

   planning 시연은 합성 환자의 일정·상태와 운영 제약을 사용합니다. 입력·규칙 결과를 실제 MIMIC/K-MIMIC 기록이나 치료 효과로 표시하지 않습니다. 계획에 쓰는 LOS 가정과 나중에 알게 되는 실제 LOS·결과를 분리해야 합니다. 환자 조회와 모델 도구에는 기준 시점 이후 활력·퇴실·사망 결과를 넣지 않습니다.

   기존 ICU 상황판은 별도 기록 재생 기능입니다. K-MIMIC을 연결하려면 승인된 CSV 경로, `kmimic.py`의 `COLS` 컬럼명·시간 형식, `concepts.json`의 병원별 itemid·단위·병동 키워드를 확인해야 합니다. 현재 매핑에는 일부 병원 항목만 있으며 실제 K-MIMIC 연결은 미검증입니다. CSV가 다르면 현장 팀원이 어댑터를 수정해야 합니다. 재입실은 환자 ID뿐 아니라 입원 회차로 구분해야 합니다.

   승인된 내부 CSV의 시간축은 `python3 timeline_check.py --admissions /approved/icustays.csv --events /approved/chartevents.csv --max-rows 1000`으로 작은 범위부터 점검할 수 있습니다. 컬럼명이 다르면 `--patient-column`, `--stay-column`, `--anchor-column`, `--end-column`, `--time-column`을 지정합니다. 결과는 집계만 담으며 실제 날짜 변환 규칙·환자 간 동일 달력은 여전히 미검증입니다.

4. **실제 모델 API 확인**

   `.env.pod.example`에는 API 키나 자동 선택 endpoint가 없습니다. 승인된 **단일 OpenAI 호환 endpoint**와 정확한 모델 ID를 받으세요. 연결 검사는 같은 endpoint·모델에 기본 응답과 native tool calling 요청을 보내므로 호출 비용이 생길 수 있습니다.

   ```sh
   cp .env.pod.example .env.pod
   ```

   `.env.pod`의 `LLM_BASE_URL`, `LLM_MODEL`, `LLM_API_KEY`를 실제 값으로 채웁니다. 쉘에서 읽을 문자열은 작은따옴표로 감싸세요. API 키는 화면 공유·발표·반출 파일에 넣지 않습니다. 키를 화면에 출력하는 명령은 필요하지 않습니다.

   ```sh
   set -a
   . ./.env.pod
   set +a
   python3 pod_check.py --model
   ```

   `LLM_*`가 우선이며 기존 `KHDP_BASE_URL`, `KHDP_MODEL`, `KHDP_API_KEY`도 호환합니다. `KHDP_MODELS`만 있으면 첫 모델을 사용합니다. 앱 기본 모드는 `PLANNER_MODE=offline`입니다. 승인된 내부 endpoint임을 확인하고 모델 점검을 통과한 뒤에만 `PLANNER_MODE=live`로 변경해 서버를 실행합니다.

   `--model`은 실제 환자 자료를 읽거나 전송하지 않습니다. 합성 연결 문장과 `POD-SYNTH-001` 식별자만 보내고, 받은 도구 호출도 실제 실행하지 않습니다. API 키·전체 환경·응답 원문·오류 원문은 출력하지 않습니다. `real_model_call_verified`와 `native_tool_call_verified`를 따로 확인하세요. 한 단계라도 실패하면 종료 코드는 1이며 규칙 출력으로 성공을 대신 표시하지 않습니다. 기본 요청 제한은 각각 15초이고 `--timeout 30` 등으로 1~60초 범위에서 지정할 수 있습니다.

   앱의 live 요청에는 합성 planning 문맥이 들어갑니다. 실자료를 모델에 연결하려면 데이터 이용·전송 경로를 별도로 확인해야 합니다. 이 안내와 환경 예시에는 실제 환자 자료가 포함되어 있지 않으며, 승인되지 않은 외부 endpoint에 실자료를 보내면 안 됩니다. 현재 점검 결과는 실제 GLM/Qwen 연결 성공을 주장하지 않습니다.

5. **예약 시연 순서**

   planning 화면과 core가 준비된 뒤 다음 순서로 확인합니다. 준비 여부는 `pod_check.py --offline` 결과를 기준으로 합니다.

   - 합성 환자 목록에서 환자 상태·기준 시각과 ICU 병상·근무 인원·수술 가능한 시간창을 확인합니다.
   - 처음에는 규칙 실행 모드를 사용합니다. 내부 모델을 실제로 점검한 뒤 UI의 실제 모델 모드를 선택하면 모델 요청 경로를 사용합니다.
   - 규칙 모드로 제안을 생성하고, 예약·직원 제약과 충돌 사유를 확인합니다. 제안 생성은 예약 확정이 아닙니다.
   - **승인하기 전에** 충돌 시연을 넣어 다른 예약이 후보 자원을 선점하고 revision이 바뀌는 것을 확인합니다.
   - 옛 제안의 승인을 요청해 HTTP 409로 차단되는 것을 확인합니다. 승인한 예약 위에 중복 충돌을 주입하는 기능은 아닙니다.
   - 재계획해 새 제안을 만들고 사용자가 새 제안·현재 revision을 확인한 뒤 승인합니다. 재계획만으로 예약을 확정하지 않습니다.
   - 시간 진행 후 환자 경과와 교대·예약 상태를 확인합니다. 주말 elective 제한과 LOS는 시연 가정이며 실제 병원 운영 규정으로 해석하지 않습니다.

   아직 생성 중인 버튼이나 기능은 완료된 기능으로 발표하지 않습니다. 현재 파일이나 화면에 없는 단계는 `pending`으로 남기세요.

6. **평가 결과 읽기**

   `planner_evaluate.py`는 별도 합성 평가 파일입니다. 먼저 옵션을 확인하고 소규모 smoke 후 seed를 고정한 평가를 수행하세요.

   ```sh
   python3 planner_evaluate.py --help
   python3 planner_evaluate.py --seeds 1 2 3 --output verification/planning-evaluation.json
   python3 -m unittest test_pod_check -v
   ```

   평가 파일 생성 전에는 실행 완료로 표시하지 않습니다. 보고서에서는 규칙 정책과 실제 모델 정책, 모델 호출 실패·누락, 환자와 일정 seed, 제약 위반, 예약 충돌, 대기 시간과 LOS 민감도를 구분해야 합니다. 실측 결과가 없으면 빈 결과를 개선 효과로 제시하지 않습니다.

7. **발표에서 말할 수 있는 범위**

   - Python·모델 ID·앱 버전과 파일 버전, 실행 명령·설정·seed를 기록하되 키는 기록하지 않습니다.
   - 합성 환자와 LOS 가정, 시간창·직원 제약은 검증된 임상 예측이나 현장 규정이 아닙니다.
   - 최종 LOS·퇴실 결과나 미래 활력을 계획 입력에 쓰면 누출입니다. 훈련·예측·평가에 사용하는 시점을 분리합니다.
   - smoke·문법 검사·단위 테스트는 실행 정확성 근거이며 실제 환자의 안전·치료 성공률·업무 절감 효과의 증거가 아닙니다. 실제 환자·병원에서 측정된 효과는 아직 없습니다.
   - 이 안내는 당일 규정·모델 지원을 확정하지 않습니다. 현장 확인 내용을 팀원이 별도로 기록해야 합니다.

8. **현장 오류 진단**

   - `pending`: 필수 planning 파일이 아직 없거나 저장이 끝나지 않았습니다. 완성된 같은 버전의 폴더인지 확인합니다.
   - Python 버전·문법 오류: Python 3.10 이상인지, 압축을 완전히 풀었는지 확인합니다.
   - `Address already in use`: 해당 포트를 쓰는 기존 본인 서버 터미널을 확인하거나 승인된 다른 `PORT`를 사용합니다.
   - 빈 화면·404: `/planning` 주소, 서버 실행 폴더, Pod 포트 전달을 확인합니다.
   - 모델 설정 미검증: endpoint와 모델 ID가 필수입니다. `.env.pod`를 만들기만 하고 환경에 적용하지 않았는지 확인합니다.
   - HTTP 401/403: 키·모델 이용 권한·endpoint를 담당자에게 확인합니다. 오류 원문이나 키를 발표 화면에 붙이지 않습니다.
   - HTTP 404/400 또는 native tool 검사 실패: OpenAI 호환 경로와 요청 파라미터·tool calling 지원을 확인합니다. API 지원을 추측해 성공으로 표시하지 않습니다.
   - 시간 초과: 승인된 내부 endpoint 접근과 제한을 확인합니다. 모델 확인이 실패해도 합성 규칙 모드는 별도로 점검할 수 있습니다.
   - K-MIMIC 파일·컬럼 오류: 승인된 CSV 위치, 컬럼명, itemid·단위·시각 매핑을 확인합니다. 합성 시연을 실제 K-MIMIC 실행으로 바꾸어 표시하지 않습니다.
