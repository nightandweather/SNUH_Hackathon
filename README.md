# PeriCare v6.1 — 일반병동 중심 병상 구성과 넓은 운영 지도

입원 전 EMR과 수술·회복 과정의 관측으로 동적 집중관리 위험, 집중관리 지속기간, ICU 이용·체류, 잔여 입원기간과 병상 예약 시점을 연결하는 Docker 프로토타입입니다.

기본 시나리오는 **기존 입원 환자 60명 + 하루 신규 24명 × 7일**, 총 228개 수술 사례입니다. ICU 12병상(외과계 8 + 심장계 4, 10개 가동), 일반병동 128병상, 수술실 8실, 이동 의료진 13명을 가정합니다. 분석 코호트 밖의 기존 ICU 재실 1명도 별도로 점유를 유지합니다. 병원 전체 환자 수와 수술 분석 코호트의 수를 혼동하지 않습니다.

데이터와 의료진은 합성 시연입니다. 환자 구성과 회복 기간은 실제 데이터셋의 통계를 추정한 결과가 아닙니다. 기본 `demo-rules-3.0`은 학습되지 않은 규칙 모델이며, 실제 모델을 연결하는 인터페이스를 제공합니다.

## v6 코드 재점검에서 수정한 부분

- 실제 ICU 환자를 다음 수술의 예정 시각 때문에 수술 전 환자로 오분류하지 않습니다. 병상 ID에 ICU 문자열이 없어도 제공된 병동·점유 연결로 인식합니다.
- 환자 위치와 병상 재실 정보가 서로 다르면 불러오기를 거부합니다. 단순 ICU 구역만 입력했을 때도 함께 제공된 실제 병상 연결키를 사용합니다.
- 같은 시각에 퇴실·전실과 다음 환자의 위치 기록이 겹쳐도 환자 ID 순서 때문에 재생이 멈추지 않습니다. 실제 중복 점유는 전체 진행 요청을 거부하고 상태를 보존합니다.
- 지연 수신한 생체신호는 수신 시각과 측정 시각을 구별하고, 측정 시각별로 정리합니다. 이전 측정이 마지막 신호로 잘못 취급되거나 중복 집계되지 않습니다.
- 실제 수술 종료를 재수신해도 이미 ICU·병동에 있는 환자를 회복실로 되돌리지 않습니다. 기록 재생에서 실제 종료 시각과 정보가 도착한 시각을 따로 제공할 수 있습니다.
- 퇴실 예상이 제공되지 않은 재실 병상은 **퇴실 시각 미확인**으로 표시합니다. 앞 환자의 예상 기간을 다음 환자에게 넘기지 않습니다.
- 닫은 환자를 같은 목록으로 즉시 다시 열 수 있습니다. 출구 아이콘이 사라진 뒤에도 선택했던 퇴원 이력이 유지됩니다. 새 자료를 연결하면 이전 강조·퇴원 필터를 정리합니다.
- 긴 연결키는 지도에 짧은 표식을 사용하고, 원래 환자·병상 ID는 상세·목록·API에 보존합니다.
- 이번 v6.1 업데이트는 기존 v6 운영 날짜·환자·예약을 유지하고 일시정지합니다. 병상 구성·7일 시나리오·자동 의료진 진행을 유지합니다.

## 병상 비율과 지도

서울대학교병원 [본원 현황 및 통계](https://www.snuh.org/content/M005004002.do)의 **2025-12-31 기준 일반병상 1,130개·성인 ICU 106개**를 참고했습니다. 비교 대상인 일반+성인 ICU에서 중환자실 비중은 `106/(1130+106)=8.58%`이며, 앱의 `12/(128+12)=8.57%`로 축소했습니다. 전국 공통 비율이나 실제 기관 전체의 복제라는 뜻은 아닙니다. 특수격리·소아·신생아 병상은 이 성인 수술 시연에서 제외합니다. ICU 내부 8:4 배분, 8개 수술실, 가동 중지 2병상과 의료진 수는 시연 가정입니다. 수술실·회복실은 입원 병상 비율의 분모에 포함하지 않습니다.

일반병동을 지도 하단의 가장 넓은 영역으로 배치했습니다. 지도에는 **현재 추적 환자**의 위치를 그리고, 일반병동 제목에 **실제 배정/128**을 표시합니다. 빈 일반병상 128개를 모두 아이콘으로 반복하지 않습니다. 따라서 환자 아이콘 수가 병원의 전체 병상 수나 전체 병원의 점유율을 의미하지 않습니다. 실제 자료를 불러오면 제공된 병상 재고를 그대로 사용하며 128:12로 바꾸지 않습니다.

고정 왼쪽 메뉴·큰 통계 카드·항상 열린 상세/최근 기록 패널을 제거했습니다. 재원·신규 입원·퇴원·ICU 재실 4개 지표만 작은 줄로 표시합니다. 테마·큰 글씨·자료 연결·초기화는 설정에, 구역·강조·이동 효과는 지도 도구에 모았습니다. 환자·병상을 선택하면 상세가 겹쳐 열리고 닫으면 지도를 다시 넓게 볼 수 있습니다.

## 실행

Docker Desktop을 실행하고 압축을 푼 `pericare-prototype` 폴더에서 실행합니다.

```bash
docker compose up --build -d
```

브라우저에서 http://localhost:8000을 여세요. Windows에서는 `start-docker.bat`을 실행해도 됩니다. 첫 Docker 빌드는 `python:3.12-slim` 다운로드가 필요합니다. 앱 실행에는 pip·npm·CDN·LLM 연결이 필요하지 않습니다.

```bash
docker compose ps
docker compose logs -f pericare
docker compose down
```

첫 화면은 일시정지입니다. **시뮬레이션 시작**을 누르면 의료진이 스스로 진행하며 사용자에게 환자 입실·퇴원 판단을 묻지 않습니다.

| 조작 | 사용 목적 |
|---|---|
| 1분 / 2초, 5분 / 2초 | 간호사 접근·동행 이송·인계를 자세히 관찰 |
| 15분 / 2초 | 수술·회복·입퇴원 흐름 관찰 |
| 1시간 / 2초, 4시간 / 2초 | 여러 날의 병상 수요와 순환 관찰 |
| +1시간, +1일 | 중간 사건을 순서대로 처리하며 지정 기간 진행 |
| 지도 도구 → 구역 이동 | 수술실·ICU·병동·입원 접수·퇴원 출구 확대 |
| 화면 가득 보기 | 메뉴를 숨기고 재생·배속과 지도를 전체 화면으로 표시 |
| 아이콘·환자 선택 / Esc | 필요할 때만 상세 패널 열기 / 닫기 |
| 설정 → 다시 시작 | 기본 합성 7일 시나리오로 초기화 |

처리가 오래 걸리면 다음 재생 갱신도 늦어질 수 있습니다. 큰 배속에서 모든 짧은 이동을 화면에 보여주지는 않지만, 서버는 중간 입퇴원·관측·병상 사건을 처리합니다. 느린 배속으로 이동을 관찰하세요. 7일이 끝나면 자동으로 멈추며, 남아 있는 장기입원 환자를 강제로 퇴원시키지 않습니다.

## 업데이트

동일 Compose 프로젝트와 volume을 유지한 채 기존 폴더의 소스를 교체하고 `docker compose up --build -d`를 실행하세요. 브라우저는 `Ctrl+F5`로 새로고침합니다. **`docker compose down -v`는 기존 데이터를 삭제하므로 업데이트에 사용하지 마세요.**

v5 이하의 합성 운영 상태는 SQLite `archived_snapshot`에 보관하고 v6의 일반 128·ICU 12병상, 60명·7일 시나리오를 처음부터 준비합니다. 기존 감사 기록은 유지합니다. 실제 가져온 자료는 합성 환자로 교체하지 않습니다. v6·v6.1 진행 상태는 이번 수정에서 초기화하지 않습니다. v6.1 재시작은 현재 날짜, 입퇴원 기록, 신규 유입 대기열과 예약을 유지하고 일시정지합니다. 코드와 DB를 함께 보관하세요.

## 세 화면

| 화면 | 핵심 내용 |
|---|---|
| 실시간 병원 지도 | 현재 추적 입원, 신규 입원·퇴원 누적/당일 수, 수술·ICU·병동 상태, 입원 접수와 출구, 환자·의료진 이동 |
| 환자 위험·경과 | 현재 입원/전체 이력/퇴원 필터, 입원·수술 후 경과시간, 동적 위험과 기간, 관측 시계열, 예약 당시 예측과 실제 진행 |
| ICU 병상 계획 | 예약·준비·이송, 실제 점유와 청소, 향후 24시간 확정 예약과 가용 예상 |

퇴원 환자는 잠시 출구에 표시한 후 지도에서 사라지고 전체 이력에 남습니다. 미래에 들어올 환자와 그 관측·결과는 현재 화면과 모델 요청에 나타나지 않습니다. 가독성을 위해 화면의 장기 경과는 구간별 위험 최저·최고와 최근 상세를 유지한 축약본입니다. 이 화면을 원자료 전체로 취급하지 않습니다.

## 실제 자료 연결

상단 **설정 → 데이터 연결**에서 공통 JSON을 불러옵니다. 자료는 최대 20MB, 수술 사례 최대 1,000개입니다. 제공된 `examples/recorded-replay.json`은 형식을 보여주는 **합성 예제**입니다. 연결키·단위·현재 시점을 확인한 실제 자료로 교체하세요.

- **현재 스냅샷**: 현재까지 알려진 병력, 검사, 관측, 실제 수술 종료와 입원 상태만 입력합니다. 없는 측정값을 정상값으로 채우지 않습니다.
- **기록 재생**: 이후 관측과 입원·수술·전실·퇴원을 `replay_events`에 분리합니다. 해당 시각에 도달할 때만 관측 상태에 반영합니다.
- 실제 자료에서는 가상 의료진이 진료·입퇴원을 만들어내지 않습니다. 기록된 위치와 사건을 재생하고 실제 미래 사건을 예측 입력에 넣지 않습니다.
- INSPIRE/VitalDB처럼 환자마다 시간이 다르게 익명화된 자료는 `patient_relative`/`case_relative`를 사용합니다. 실제 동시성·병상 경쟁·예약 계산은 차단합니다.
- 실제 운영 예약에는 승인된 공통 병원 달력과 병상·장비·청소·입퇴실 이력이 필요합니다. 병상 재고를 제공받지 못했으면 `beds: []`로 두며 빈 병상이 있다고 추정하지 않습니다.

이미 연결키와 단위를 맞춘 CSV의 스냅샷 변환:

```bash
python scripts/normalize_csv.py --patients examples/patients.csv --observations examples/observations.csv --beds examples/beds.csv --base-time 2026-10-16T08:30:00+09:00 --clock-kind hospital_shared --output normalized.json
```

미래 관측과 관측 사건 CSV를 분리한 기록 재생 변환:

```bash
python scripts/normalize_csv.py --patients patients.csv --observations observations.csv --events events.csv --beds beds.csv --base-time 2026-10-16T08:30:00+09:00 --clock-kind hospital_shared --minute 0 --replay --horizon-minutes 10080 --output recorded.json
```

환자별 실제 미래 종료를 입력할 때 `actual_end_minute`는 현재 상태에서 제거하고 별도 재생 사건으로 분리합니다. `estimated_end_minute`에는 예측 시점에 알고 있던 종료 추정만 사용하세요. 최종 수술시간을 복사하는 기능은 제공하지 않습니다. 미래 입원에는 별도의 `admission_location`과 명시적인 입원 시각이 필요합니다. 반복 수술·겹치는 입원·지연 입력의 정합성은 upstream에서 정리해야 합니다.

현재 관측 내보내기는 최근 관측·처치를 포함한 스냅샷입니다. 비공개 미래 재생 사건과 신규 유입 대기열은 제외합니다. 전체 원자료나 SQLite 백업을 대체하지 않습니다.

## 예측 모델 연결

`.env.example`을 `.env`로 복사하고 설정합니다.

```dotenv
MODEL_BACKEND=remote
MODEL_URL=http://model-service:9000/predict
MODEL_API_KEY=
```

[모델 계약](docs/MODEL_CONTRACT.md)의 HTTP JSON 형식을 사용합니다. 모델이 연결되지 않으면 수치를 `—`로 표시하고 예약 추천을 보류합니다. 임의의 모의 결과로 대체하지 않습니다. 입원 예정·종료 사례에는 현재 예측 요청을 보내지 않습니다. 실제 체류·확정 예약과 예측 기간을 구분합니다.
