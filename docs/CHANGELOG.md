# PeriCare v6.1 코드 검토·수정

| 재현한 문제 | 수정 |
|---|---|
| 현재 ICU 위치가 다음 수술 예정 시각 때문에 PREOP으로 바뀜 | 관측된 ICU 점유 우선, 기관별 병상 ID 연결 지원 |
| 환자 위치와 병상 재실 불일치 입력이 통과 | 양쪽 ID·구역 검증, 입력 실패 시 현재 데이터 보존 |
| 수술 종료 정보를 다시 받으면 ICU·병동 환자가 PACU로 표시 | 관측 시각과 실제 종료 구별, 현재 진행 단계 보존, 최초 완료만 집계 |
| 같은 시각 전실이 환자 ID 순서에 따라 충돌 | 해당 시각의 최종 점유를 함께 확인하고 반영, 실제 중복은 원자적 거부 |
| 지연 관측이 수신 시각으로 중복 제거되어 같은 측정이 남음 | 측정 시각으로 대체·정렬, 정보 도착 시각 전에는 입력 배제 |
| 새로운 ICU 재실이 이전 환자 퇴실 예상을 물려받음 | 새 재실의 미제공 전망은 미확인으로 표시하고 예약 후보에서 제외 |
| 상세 닫기 뒤 같은 환자를 다시 고르기 어려움 | 선택 목록 초기화, 동일 환자 재선택 지원 |
| 출구 아이콘이 사라지면 선택한 퇴원 상세가 없어짐 | 관측된 종료 이력 유지, 사망·전원과 귀가 구별 |
| 새 자료에 이전 강조·퇴원 필터가 남음 | 자료 교체 시 현재 사례 기준으로 선택·필터 정리 |
| 긴 기관별 연결키가 지도에서 서로 겹칠 수 있음 | 단축 지도 표식과 원본 ID 분리, 전체 키는 상세·선택 목록에 보존 |
| 버전 문자열이 달라지면 매번 시나리오가 초기화될 가능성 | v6.0/v6.1 상태 호환, 현재 날짜·환자·예약 유지 |

앱 v6.1.0, 데이터 계약 1.0/1.1 입력 지원, 선택적 actual_end_minute와 availability_forecast_known은 v6.1에서 해석합니다. 규칙 모델 demo-rules-3.0, 병상 128:12, 기존 60명+하루 신규 24명×7일을 유지합니다. 실제 데이터셋 원본·학습 모델은 포함하지 않습니다.

# PeriCare v6.0 변경점

| 문제 | 변경 |
|---|---|
| v5의 ICU 24 / 일반 96 구성에서 ICU 비중 20% | 성인 일반+ICU 공개 규모를 참고해 ICU 12 / 일반 128, ICU 비중 8.57%로 축소 |
| 고정 세로 메뉴와 상시 상세 패널로 지도가 좁음 | 가로 메뉴, 화면 전체 폭 지도, 선택할 때만 열리는 상세 패널 |
| 6개 큰 카드와 여러 제어·설명 줄로 실제 지도가 아래로 밀림 | 4개 작은 지표와 시계·재생 줄, 설정·지도 도구에 부수 조작 정리 |
| 세로로 긴 ICU 중심 도식 | 일반병동에 더 넓은 영역, 가로형 배치와 실제 추적 환자 수에 맞춘 높이 |
| 큰 화면에서 이동을 자세히 보고 싶음 | 전체 화면/브라우저 내 대체 확대, 재생 조작 유지, 크기 변경 시 지도 자동 맞춤 |
| 이전 DB 병상 수가 새 시연과 다름 | 이전 합성 상태 보관 후 v6 시작, 실제 가져온 병상 재고는 보존 |

기존 60명+하루 신규 24명×7일, 실제 관측 기반의 가상 의료진 진행, 병원 퇴원·청소·병상 재사용, 동적 위험과 기간·예약 계획, 실제 기록 재생을 유지합니다. ICU 물리 12개 중 인력 부족 1개·정비 1개는 가동하지 않아 가용 인벤토리는 10개입니다. 현재 재실과 가동 병상은 별도 집계합니다.

병상 비율의 근거는 서울대학교병원 본원 공개 현황(2025-12-31, 일반 1,130·성인 ICU 106)이며 전국 평균을 뜻하지 않습니다. 임상 환자 분포, ICU 세부 배분과 인력 수는 합성 가정입니다. 실제 데이터에는 이 비율을 강제하지 않습니다.

앱 v6.0, 데이터/지도 계약 1.1(입력 1.0 호환), 모델 계약 1.0, 규칙 모델 demo-rules-3.0입니다. 의료 모델 학습·임상 성능 검증을 수행한 것으로 표현하지 않습니다.
