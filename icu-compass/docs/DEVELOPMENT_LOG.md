# ICU Compass 개발 과정과 시행착오

작성일: 2026-10-17 (KST). 대화와 현재 작업 파일에서 확인한 진행 순서를 정리했습니다. 아래 단계는 당시 작업의 경과이며 모두 현재 완성된 기능이라는 뜻은 아닙니다.

## 1. 출발: 간호 근무 환경을 보여주는 시뮬레이션

처음에는 평온한 근무와 출혈·응급·업무 집중 상황을 비교하고, 간호사 배치·대기 인력 호출·의사 이동·인계까지 보여주려 했습니다. 범위가 너무 넓어지면서 복잡한 디지털 트윈보다 ICU 상황판의 핵심 정보 시각화에 집중하도록 방향을 좁혔습니다. 피로도라는 추정 개념 대신 기록된 처치 수를 보여주자는 피드백도 반영했습니다. 단, 처치 기록 행 수는 독립 처치 수나 간호사의 실제 업무량과 같지 않습니다.

## 2. 사용자 피드백이 화면 구조를 바꿨다

병원 → ICU → 병상 → 환자 상세 흐름을 유지했습니다. 별도 카드에만 있던 장비 표시를 지도 안의 병상 네모칸으로 옮기고, CPR·ECMO/CRRT·승압제·인공호흡기·당일 수술을 직접 그린 SVG로 표현했습니다. ECMO/CRRT 분리 요청 뒤 최종적으로 합친 표시를 채택했습니다. 빈 병상은 연한 회색, 입실 예약은 연한 노란색입니다.

닫기 버튼이 잘 안 보임, 닫은 뒤 검은 요소가 남음, 의료진 이름과 병동 제목이 겹침, 시나리오 설정이 적용되지 않음 같은 문제가 반복됐습니다. 닫기·Escape 처리, 고정 헤더, 인력 표시 간격, 비동기 요청의 오래된 응답 차단을 보강했습니다. 간호사는 N, 의사는 Dr.로 표시하고 기존 캐릭터 중심 디자인을 유지하려 했습니다.

## 3. 공유 화면과 KHDP 화면이 달라졌다

공유 사이트와 KHDP 앱을 각각 고치면서 버전이 어긋났습니다. 공개 프레젠테이션의 기준을 공유 사이트로 정하고 KHDP 8006 진입점은 그 화면으로 연결했습니다. 실제 기록·토큰·LLM은 인증된 8007에 남겼습니다. 이는 같은 화면 버전을 제공하는 구조이며 여러 사람의 시뮬레이션 상태를 동시에 동기화하는 구조는 아닙니다.

## 4. 데이터가 들어오자 기존 UI가 깨졌다

새 증거 보드를 별도로 만들면서 기존 병동 지도, 간호사·의사, 월간표가 없어지거나 밀려나는 문제가 생겼습니다. 사용자 요구는 새 UI가 아니라 기존 UI에 GS ICU 자료를 맞추는 것이었습니다. 공개 화면의 스타일과 아이콘을 가져오고 실제 기록 API를 연결하는 어댑터 방식으로 수정했습니다.

전체 GS 코호트는 14,321 ICU stays, 병원·환자 기준 12,264명으로 집계한 인덱스를 별도로 보존합니다. 상황판 샘플이나 월간 시나리오로 전체 코호트를 축소하지 않습니다. 이 저장소에는 코호트 원본을 넣지 않습니다.

## 5. 장비 ‘미확인’ 문제는 아이콘 문제가 아니었다

원본에 사용 기록이 있어도 화면에 점등되지 않았습니다. 장비 사전에 항목이 있다는 것, 특정 환자에게 사용했다는 것, 선택 시점까지 유지 중이라는 것은 서로 다른 사실이었습니다. 사용·유지·제거·ON/OFF·ECMO 유량 등을 확인하고, 선택 시점 이전의 확인 기록에 맞춰 표시하도록 정리했습니다. 중단 기록이 없다는 이유만으로 현재 사용을 영구적으로 확정하지 않습니다.

## 6. 8병상 월간표와 실제 기록의 시간은 분리해야 했다

ICU.xlsx를 바탕으로 10월 1일부터 31일까지 시나리오를 재생하고, 이송원 이동과 병상 색상 변화를 연결했습니다. 실제 원본의 ICU 상대 시각과 시나리오 달력은 별개입니다. 빈 칸 보완에는 기존 활력 기록을 이용한 파생 사례가 포함됩니다. 재배치한 사례가 실제 동일 날짜에 동시에 입실했다고 해석하지 않습니다.

10분 재생 시 의료진 이동은 모의 동작입니다. 활력 기록의 간격과 검사실 검사 빈도는 다릅니다. 새 결과가 없으면 마지막 실제값과 경과시간을 표시하고, 제한된 보간은 화면 재생에만 씁니다. 미래 관측을 쓰는 보간값은 AI 판단이나 알림의 근거로 넘기지 않습니다.

## 7. 역할극에서 간호 지원 AI로 방향을 좁혔다

간호사·환자·의사 다자 역할극에서, 간호사가 의사에게 확인할 내용을 묻는 지원 에이전트로 변경했습니다. 환자와 평가 시점을 고정하고 그때 가용했던 기록만 전달합니다. 시점을 바꾸면 대화를 새로 시작합니다. 과거 수치·시각 없는 진단·환자 발언·공식 판독문을 모델이 만들어 채우지 않도록 구분합니다. 출력은 처방 실행이나 자동 전실 결정이 아닙니다.

## 8. GPU·VPN·API에서 생긴 시행착오

GPU Pod 생성 실패와 재시도, SSL VPN OTP 및 연결 끊김, 웹 로그인 만료, 마운트 추가 후 서버 재기동 문제를 겪었습니다. Qwen이 서버에 있다는 안내만으로 API 주소나 이미지 지원을 확정할 수 없었습니다. 개인 토큰 발급 문서는 인증 설명이었고, 실제 모델 호출 주소와 capability 확인이 추가로 필요했습니다.

KHDP OpenAI 호환 API로 모델 목록과 실제 호출을 확인했습니다. `qwen3-8-max-ax`는 이미지 입력을 거부했고 `qwen3-8-flash-next-ax`는 테스트 이미지 입력에 응답했습니다. 모델 이름만으로 영상 지원 여부를 추정하지 않는 것이 핵심이었습니다.

## 9. CXR 파일을 찾았지만 환자 연결은 끝나지 않았다

새로 마운트된 영상 인덱스 195,552건을 읽었습니다. 현재 상황판의 hospital 001 사례와는 환자 ID가 일치하지 않았습니다. 전체 GS 코호트에서는 ID 문자열이 겹치는 12 stays/10명과 영상 132건을 찾았지만, 검사 경로의 정확한 일치는 0건이었고 영상·EMR 날짜가 수년씩 달랐습니다. DICOM의 환자 ID·촬영 날짜 태그도 비어 있었습니다.

README 확인에서도 두 데이터셋 사이의 공식 연결표·날짜 변환 규칙은 확인되지 않았습니다. ID 문자열 일치만으로 같은 환자로 확정하지 않았고 환자 교체도 실행하지 않았습니다. 사용자에게는 교체 승인을 받았지만 데이터 연결 근거는 별도로 필요했습니다.

익명화 DICOM의 빈 rescale/window 태그 때문에 렌더링이 실패해, 빈 변환 태그를 처리하는 비진단용 미리보기 변환을 보강했습니다. 실제 CXR 한 장을 읽어 Qwen에 전달하고 구조화된 응답이 돌아오는 것은 확인했습니다. 이 검증은 환자와 연결하지 않은 기능 검사이며 임상 정확도 평가가 아닙니다.

## 10. 연구 모델과 연결할 지점

팀원이 개발 중인 연구 주제는 모달리티 누락을 고려한 CalMRL 기반 ICU 악화·전과 후 안전성 예측입니다. 제공받은 계획은 8시간마다 평가하고, 향후 8/24시간 내 사망·새 승압제·침습적 환기 시작, 실제 전과 후 48시간 내 재입실·사망 없는 확률을 다루는 것입니다.

현재 연구 범위는 MIMIC-IV 성인 ICU EMR과 MIMIC-CXR 특징 최대 1,000개이며, 생체신호 통합·K-MIMIC 적용·외부 검증은 후속 과제입니다. 상황판의 RED/BLUE/GREEN 표시가 이 모델의 검증된 예측값인 것처럼 합치지 않습니다. 모델 가중치·학습 결과는 이 코드 묶음에 포함되지 않습니다.

## 남은 우선순위

1. IMAGE와 EMR의 공식 환자·검사 연결표 및 날짜 이동 규칙 확보.
2. 같은 환자·검사·시점이 검증된 CXR로 월간표 일부 사례를 교체하고 뷰어→AI 흐름을 실제 화면에서 검증.
3. 장비·투약 매핑의 기관별 커버리지와 가용 시각 검증 확대.
4. 상태 색상 규칙과 예측 모델 출력을 분리한 평가, 의료진 검토 및 확률 보정 검증.
5. 자동 배포 및 버전 표시 개선. 브라우저 상태 동기화는 별도 설계 필요.

## 2026-10-17 — 새 UI 통합과 실제 대화 점검

SICU LINK 팀원 PR의 시각 요소만 인증 상황판에 옮겼습니다. 환자 풀이나 데모 API를 교체하지 않고 기존 월간 재생, 카트 이송, 간호사·의사 이동을 유지했습니다. 말풍선 형태의 상담 화면과 실제 AI 입력 바이탈 요약을 추가했습니다. 화면에는 값이 있는데 AI는 미확인으로 답하는 사례는 CHARTTIME만 있는 후향적 값과 당시 가용성이 확인된 값의 차이였으며, 근거 필터를 완화하지 않고 차이를 화면에 표시했습니다.

CXR 시험 결과를 발표에 넣은 것과 환자 챗봇에 CXR 입력이 생긴 것을 혼동하지 않도록, 챗봇에 별도 첨부 CXR 선택란을 추가했습니다. 실제 매칭이 없을 때는 선택 불가 사유를 표시하며, 검증된 영상만 기존 비공개 영상 검토 API로 보냅니다. 환자·시점·영상·문맥 해시가 다른 응답은 표시하지 않습니다.

실제 CXR 독립 입력 시험은 응답 생성까지 확인했지만, 이전 메모에 남긴 PA/AP 불일치 주장은 저장된 응답 원문 재확인으로 뒷받침되지 않아 삭제했습니다. 입력 지원을 판독 정확성으로 설명하지 않으며, 같은 환자의 EMR+CXR 결합 평가는 공식 매핑 확인 이후로 남겼습니다. 실제 환자 화면·영상이 포함된 발표 파일은 저장소에 추가하지 않았습니다.

## 13. CXR을 함께 보고 모델별 답변을 비교

사용자 요청에 따라 동일인 연결과 구분한 무작위 모의 CXR 레지스트리를 추가했습니다. 사례 바인딩과 이미지 해시를 검증하고, 영상에 환자 관찰 시각을 임의 부여하지 않습니다. CXR과 EMR을 분리해서 해석하도록 프롬프트에 명시했습니다. Qwen Flash Next와 DeepSeek Flash에 같은 입력을 보내 응답을 받았으며, 심장 크기와 관 종류에 대한 서술 강도가 달랐습니다. 공식 판독과 비교하지 않았으므로 임상 성능 결론은 내리지 않았습니다.

EMR만 사용한 동일 질문의 6000토큰 재시험에서는 Qwen과 DeepSeek 답변을 수신했고 GLM은 길이 제한으로 끝났습니다. 실제 발췌를 발표에 넣되 민감 데이터가 포함될 수 있는 발표 파일은 저장소에 넣지 않았습니다.
